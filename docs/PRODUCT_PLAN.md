# 家具 AI 设计系统：产品计划

版本：0.1 · 决策日期：2026-10-15

## 1. 已确认的产品方向

建设分为三个阶段的定制家具设计系统。客户先用自然语言快速确定家具外观，决定定制后，再进入精确设计和生产工程设计。三个阶段共享项目档案，分别使用适合各自目标的工具与审核标准，不要求同一份网格直接转成生产模型。

| 阶段 | 使用者 | 核心目标 | 交付物 | 成本与速度策略 |
| --- | --- | --- | --- | --- |
| 一：外观共创 | 客户、销售、设计师 | 快速生成、比较、修改有吸引力的外观 | 三维外观、视图、材质意向、版本档案 | 控制交互成本，优先实时渲染与局部编辑 |
| 二：设计深化 | 设计师、客户 | 明确尺寸、可见细节、功能与材料 | 精确 CAD、外观尺寸图、饰面表、设计确认包 | 质量优先，允许较长计算和人工参与 |
| 三：生产工程 | 工厂工程师、工艺人员 | 完成结构、装配、加工和可靠性设计 | 生产图纸、BOM、工艺要求、检查和审批记录 | 质量与可追溯优先，不限制必要工程投入 |

第一阶段的内部场景允许保存比例、分区与部件信息，以支持稳定修改；客户不需要理解参数化 CAD，也不需要输入全部尺寸。内部的外观几何参数不构成制造参数。

## 2. 文档状态与本轮交付边界

本文固化已确认的产品范围和验收标准，不代表全部能力已经实现。当前开发目标是第一阶段的单品类可运行原型；第二、三阶段是后续路线图。功能是否完成，以运行结果、检查记录和代码为准。

第一阶段首个品类选为**边柜**。目的是先证明“描述 → 外观 → 局部修改 → 版本 → 导出”的闭环，再扩展桌、架、床等品类。软体家具、雕刻与复杂自由曲面不包含在首轮范围中。

## 3. 第一阶段：外观共创原型

### 3.1 用户体验

1. 打开工作台即可看到具有材质、光照、阴影的可旋转边柜，不以空场景开始。
2. 选择一个设计方向，或直接输入“更圆润、浅木色、隐藏柜脚”等描述。
3. 系统更新已支持的外观属性，并说明本次变化。不能理解或尚不支持的需求应明确说明。
4. 用户可继续局部修改、切换材质、调整视角、锁定已确认部分。
5. 用户可以撤销、重做、保存版本，并在不同版本间恢复设计。
6. 导出当前画面的 PNG、当前外观模型的 GLB、可恢复编辑信息的 JSON 外观包。

产品语言以中文为主，视觉以家具设计工作台为主，不将供应商配置、内部模型字段等实施细节放进客户的主要操作流程。

### 3.2 首轮功能范围

| 能力 | 本轮目标 | 边界 |
| --- | --- | --- |
| 实时三维 | 旋转、缩放、标准视角、光照、阴影 | 不等于离线电影级渲染 |
| 外观变化 | 支持边柜轮廓、比例、分区、柜脚、把手等预设几何变化 | 不支持任意雕刻或所有自由曲面 |
| 材质变化 | 木色、纯色、饰面与金属等可视差异 | 屏幕效果不代替实物色板 |
| 语言修改 | 服务端模型理解需求并生成受约束的场景修改 | 模型不得生成并执行任意代码 |
| 演示模式 | 无模型密钥时使用本地规则解析受支持的中文命令 | 界面必须明确显示本地演示，不冒充已接入 AI |
| 局部保护 | 锁定已确认部分，后续修改尊重锁定 | 不支持的锁定粒度不应在界面虚构 |
| 历史 | 修改快照、撤销、重做与保存版本 | 首轮按单机使用，不承诺多人实时协作 |
| 持久化 | 服务端本地 JSON 保存项目 | 不视为生产级数据库或灾备方案 |
| 导出 | PNG、GLB、JSON 外观包 | 不生成生产图、STEP、BOM 或数控文件 |
| 轻量成本提示 | 如展示，仅针对可识别复杂外观给出定性提示 | 无供应商和材料数据时不输出可信报价 |

参考图理解、图片转三维、独立图像生成、任意资产生成、工厂报价和付款流程不在首轮交付范围。后续可扩展高质量效果图，但图像中的产品结构必须与当前三维版本保持一致。

### 3.3 模型接入方式

- 前端通过本项目服务端发起请求，模型密钥仅保存在服务端环境变量中。
- 后端允许配置 OpenAI-compatible 的服务地址、模型名称和 API Key。
- 模型只建议受支持的场景字段；服务端完成校验、范围约束与锁定检查后才能应用。
- 无配置时进入明确标示的本地演示模式。已配置但调用失败时显示错误或明确说明降级，不能静默声称 AI 已成功处理。
- 对于“改成会自动折叠的结构”等超出外观范围的请求，应解释范围，避免伪造结构设计结果。

### 3.4 第一阶段验收

必须在真实浏览器中验证可视效果和交互；构建成功不代表三维页面通过验收。

| 验收项 | 检查方法 |
| --- | --- |
| 初始场景可用 | 首次加载可看到完整边柜，画面没有遮挡、严重裁切或控制台致命错误 |
| 连续修改稳定 | 连续修改材质、腿型、柜门等，只有请求涉及的部件发生预期变化 |
| 锁定有效 | 锁定部分后发出相关修改请求；系统保留该部分并说明结果 |
| 历史可恢复 | 至少连续修改三次，逐步撤销和重做，恢复到正确状态 |
| 版本可保存 | 保存两个不同版本，重新打开项目后能恢复正确外观 |
| 导出一致 | PNG 对应当前画面；GLB 可重新载入；JSON 包包含当前场景与版本信息 |
| 模式透明 | 未配置模型时清晰展示演示模式；配置后显示实际请求状态 |
| 失败可恢复 | 非法输入、模型失败、保存失败不会破坏最后一个有效设计 |
| 验证不过界 | 页面和导出物明确属于外观方案，不出现未经验证的生产或承重保证 |

性能不先承诺绝对秒数。应记录首次可交互时间、普通局部修改耗时、语言请求耗时和导出耗时，并标明测试机器。普通材质切换应由本地实时渲染完成，避免为每次操作触发模型请求或离线渲染。

## 4. 第一阶段到第二阶段的确认关卡

客户选定的外观版本应被固定为后续设计的参照，保留原版本以便比较。确认包至少应包括：

- 项目、版本、创建时间和场景格式版本。
- 模型、标准视图、材质意向以及客户已锁定的特征。
- 大致尺度和所有默认假设，明确其是否已由客户确认。
- 尚未解决的问题，包括现场尺寸、功能、材料和结构。
- “外观概念，未经生产工程验证”的状态。

首轮原型的版本保存与导出提供该关卡的数据基础；正式电子签署、订单状态和客户审批流程是后续功能，不因导出一次文件就自动视为客户已签字确认。

## 5. 第二阶段：设计深化

### 范围

以选定外观、现场尺寸、搬入限制、功能需求和材料偏好为输入，建立精确 CAD。网格可以用于参照，但必须允许重建，不能假定格式转换能得到可靠的精确实体。

输出包括外观模型、主要尺寸、门抽开合和功能空间、正侧俯视图、必要剖面与局部详图、材料饰面表、待工程解决的问题清单。规则家具优先使用 CadQuery 或 FreeCAD；复杂曲面工具需根据家具类别另行选型。

### 验收与关卡

- 精确尺寸齐全、单位统一，关键假设有来源。
- 与第一阶段确认版本比较标准视图和轮廓，说明偏差。
- 材料、功能与可见细节得到确认；颜色敏感订单保留实体色板确认记录。
- 几何有效，基本开合和空间关系通过检查。
- 明确哪些隐藏结构和性能尚未验证。

进入第三阶段前冻结主要尺寸、材料、功能和可见细节。之后仍允许变更，但必须识别受影响的模型、图纸、计算和采购项。

## 6. 第三阶段：生产工程设计

### 工厂知识建设

先与一家合作工厂打通试制闭环，再扩展多工厂。历史图纸和经验按照三类管理：

| 数据 | 存储与处理 | 使用方式 |
| --- | --- | --- |
| 历史图纸、说明、返修记录 | 原件、OCR/图纸解析、检索索引 | 查找相似案例及问题 |
| 板材、五金、设备与加工能力 | 带版本的结构化数据库 | 使用准确规格与工艺边界 |
| 孔距、边距、公差、间隙和禁用组合 | 可执行规则库 | 自动验证设计 |

每条经验保留工厂、材料、版本、投产状态、质量反馈和适用条件。未经验证的历史设计不能直接升级为生产规则。

### 工程流程

1. 检索与当前尺寸、材料、结构相匹配的案例。
2. 建立结构、连接、五金和装配方案，并保存依据与假设。
3. 检查干涉、开合、安装顺序、工具可达性和加工可行性。
4. 对载荷、挠度、稳定性、防倾倒和连接耐久等开展必要计算。
5. 按风险和适用标准进行仿真、试制与实体试验。
6. 输出装配图、零件图、BOM、加工装配要求与检查记录。
7. 工程师审核并发布受控生产版本。

大模型负责检索、规划和调用工具，不得以文字判断代替数值计算或工程审核。数控代码需后续独立接入机床、刀具、坐标和后处理器，并单独验证。

### 验收

所有关键尺寸和物料可追溯；工程规则检查结果完整；计算具有明确输入和假设；图纸与 BOM 使用同一受控版本；由工厂工程师审核，并完成相应试制和验证。没有这些证据的版本不能标记为可生产。

## 7. 关键风险与处理

| 风险 | 处理策略 |
| --- | --- |
| 客户修改一句话导致整体漂移 | 受约束的字段修改、局部锁定、不可变版本与快照 |
| 图像漂亮但模型不一致 | 当前三维作为外观依据，效果图按版本生成并校对 |
| 生成模型输出不合法 | 共享 schema、服务端检查、原子应用、保留有效版本 |
| AI 将不支持的能力说成已完成 | 模式标识、工具结果驱动状态、明确能力范围 |
| 后续工程重建破坏外观 | 保存标准视图和视觉特征，差异检查与再确认 |
| 资料错误或检索结果过时 | 原始来源、版本、适用条件与工程师审批 |
| 多工厂规则冲突 | 按工厂/设备/材料绑定规则，不混用默认值 |
| 客户设计与工厂资料泄露 | 后续加入访问控制、存储隔离、审计及模型服务数据策略 |

## 8. 下一步顺序

1. 本轮：完成第一阶段单品类原型、运行检查和文档。
2. 下一轮：围绕真实客户修改案例，提高语言理解、材质与资产质量；记录失败样例和实际延迟。
3. 外观闭环稳定后：增加标准视图确认包、参考图辅助、更多家具品类和正式用户存储。
4. 选定一家工厂及一种家具结构，验证第二阶段 CAD 重建与尺寸图。
5. 整理其已验证历史案例和规则，试点第三阶段生产图纸与试制流程。

优先扩展真实案例中反复需要的能力，而不是同时铺开所有品类和所有生成工具。
